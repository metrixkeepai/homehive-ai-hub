4. P2 — Server efficiency & operating cost 22 tasks · pending

These turn Ops 4 → 10 and Stack 8 → 10 while cutting AI, DB, and bandwidth spend.

Cost principle

Never load what you won’t show. Never call AI without a quota. Cache flags/plans. Put indexes under every filter. Rate-limit the expensive edges first (AI, voice, capture, auth).

4.1 Database & query efficiency

P2-01 Stop loading all home_items then filtering in memory P2High savingsPending

store.tsx fetches the user’s entire table then filters by workspace client-side. At scale this burns Postgres IO, bandwidth, and browser memory.

  • Query with .eq("workspace_id", activeId) (and null personal workspace rule) in Supabase
  • Paginate section lists (cursor/limit) instead of full dump
P2-02 Add missing indexes P2High savingsPending
  • home_items (workspace_id)
  • home_items (user_id, workspace_id, section)
  • evidence_files (item_id)
  • evidence_files (user_id, created_at)
  • Any admin date-range filters used in admin-ops.functions.ts
P2-03 Home / admin aggregates via SQL, not select("*") into JS P2SavingsPending

Replace large in-memory reductions (5k–10k row pulls) with Postgres count, sum, RPC views. Cap admin list endpoints with pagination.

P2-04 Cache plan entitlements + feature flags (short TTL) P2SavingsPending

Avoid re-reading plan_versions / flags on every AI request. In-memory TTL (30–60s) per process or Upstash Redis for multi-instance.
